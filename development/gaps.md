| `<group>` containers were flattened on export                                             | **fixed 2026-10-12**                                                                   | `ChemDrawGroup` (`childIds: string[]`) already existed in the document model and in-app group/ungroup commands already built it — the only missing piece was the CDXML reader/writer: `objects` never had a `type === 'group'` writer branch (silently dropped), and the top-level `<group>` reader branch only warned and preserved raw XML, never modeling it. Fixed by (1) having the reader build a real `ChemDrawGroup` from each `<group>`'s direct children (already-parsed elsewhere, since every modeled-object parser is document-wide and ignores intervening `<group>` wrappers; only the id references needed collecting), recursing for nested `<group>`s, and preserving any genuinely unmodeled child content via `rawChildrenXml` instead of dropping it; (2) having the writer render each grouped object's markup nested inside `<group>`, by letting every per-type loop append normally and then slicing a grouped object's span back out into a per-id map for the group-emission pass to reinsert. | `<graphic GraphicType="Line">` does not round-trip through real ChemDraw                  | **investigated 2026-10-12, not fixable by changing what we write**                     | ChemDraw converts a Line graphic to a `SupersededBy`-marked stub plus a new `<arrow>` on every resave. | `reserved-colors.cdxml` is not a fixed point after one round trip                         | **fixed 2026-10-12**                                                                   | Root cause was two stacked bugs.
