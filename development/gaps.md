| `<group>` containers were flattened on export                                             | **fixed 2026-10-12**                                                                   | `ChemDrawGroup` (`childIds: string[]`) already existed in the document model and in-app group/ungroup commands already built it — the only missing piece was the CDXML reader/writer: `objects` never had a `type === 'group'` writer branch (silently dropped), and the top-level `<group>` reader branch only warned and preserved raw XML, never modeling it. Fixed by (1) having the reader build a real `ChemDrawGroup` from each `<group>`'s direct children (already-parsed elsewhere, since every modeled-object parser is document-wide and ignores intervening `<group>` wrappers; only the id references needed collecting), recursing for nested `<group>`s, and preserving any genuinely unmodeled child content via `rawChildrenXml` instead of dropping it; (2) having the writer render each grouped object's markup nested inside `<group>`, by letting every per-type loop append normally and then slicing a grouped object's span back out into a per-id map for the group-emission pass to reinsert. A real stability bug surfaced along the way: redirecting a grouped object out of its type's natural write-order block (to the groups-always-last position) changes the physical document order re-import sees, which reorders that type's array and renumbers its nodes/bonds differently on the next export. Fixed by stable-sorting each per-type array (grouped objects last, relative order preserved within each half) so the first export's physical layout already matches what re-import reconstructs. `ChemDrawGroup` carries no `bounds`/`BoundingBox` (bounds are always re-derived elsewhere in this codebase, never stored) — the writer omits `BoundingBox` on `<group>` rather than inventing one; real ChemDraw adds its own on save and keeps it from then on, same as it does for other derived geometry. Confirmed against real ChemDraw (26.1.0.6801): a hand-built `<group>` (fragment + caption), a group of a graphic + arrow, two separate top-level groups, and a group nested inside another group all open correctly, and ChemDraw's own re-saved output re-imports and re-exports as a fixed point. Regression tests in `tests/cdxml-round-trip-regressions.test.mjs`. |

| `<graphic GraphicType="Line">` does not round-trip through real ChemDraw                  | **investigated 2026-10-12, not fixable by changing what we write**                     | ChemDraw converts a Line graphic to a `SupersededBy`-marked stub plus a new `<arrow>` on every resave.
