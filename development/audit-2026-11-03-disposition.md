# Disposition: quit, recovery and scientific-job audit (2026-11-03)

Eleven findings about multi-window document safety, scientific correctness and bounded work. This
file records what was changed and the evidence for it. **Implementation status** (code plus
headless regression tests) is kept separate from **platform acceptance** (behaviour observed in a
packaged app on a real OS), which has not been run for any of them.

## Deviations from the plan

- **The persistent NMR server was removed.** Every NMR prediction is now a one-shot sidecar run
  like properties, IR and MS, so cancelling one window's job kills only that job's process. Two
  costs follow: HOSE pays the sidecar's start-up on every call, since the old warm-up is gone, and
  DFT stage progress travels as `@progress {json}` stderr lines forwarded to
  `scientific-job-progress`. The `--server` mode in `chem-engine.py` is now unused.
- **Explicit HF/DFT jobs have no time limit.** The Python-side 45 s HF optimisation limit and the
  60/90 s frontend timeouts are gone; these jobs run until they finish or are cancelled. Routine
  sidecar calls keep the 2 min limit, conformers keep 10 min.
- Recovery offers snapshots one at a time; each one recovered opens in its own window.

## Not executed

- Packaged-app behaviour on any OS: multi-window quit, quit from the menu/dock, recovery after a
  real crash, and window-destroy cancellation all need a running Tauri shell.
- Windows process-tree termination (`taskkill /T`) and the `CREATE_NEW_PROCESS_GROUP` flag.
- Real PySCF/xtb calculations and performance benchmarks, deliberately excluded.
